## Security boundary

Public exposure terminates at Caddy.

FastAPI remains bound only to `127.0.0.1:2588`.

Provider invocation is allowed only after application-level authentication
succeeds.

## Device authentication

Each Android installation owns an EC P-256 key pair generated by Android
Keystore. The private key never leaves the device.

Authenticated `POST /v1/interpret` requests use ECDSA SHA-256 signatures over:

    QA1
    POST
    /v1/interpret
    <device-id>
    <unix-timestamp>
    <nonce>
    <lowercase-sha256-hex-of-exact-request-body>

Required headers:

- `X-QA-Device-Id`
- `X-QA-Timestamp`
- `X-QA-Nonce`
- `X-QA-Signature`

## Replay protection

- maximum timestamp skew: ±120 seconds;
- nonce: at least 128 random bits;
- accepted `(device_id, nonce)` values cannot be reused;
- replay state persists beyond the timestamp window;
- replay protection survives gateway restart.

## Device enrollment

`POST /v1/pair` registers a public key using a short-lived one-time pairing
code generated through a local server administration workflow.

Pairing codes are random, stored only as hashes, expire, and are consumed
atomically.

No permanent shared API secret is embedded in Android.

## Authentication persistence

A Quick Aside-owned SQLite database under `/var/lib/quickaside` may store only:

- device public keys/status;
- pairing-code hashes/expiry;
- replay nonce state.

Captured Quick Aside content must not be stored in this auth database.

## Security invariants

1. Quick Aside works without Tailscale.
2. Only Caddy receives public Quick Aside traffic.
3. FastAPI remains on `127.0.0.1:2588`.
4. Provider invocation occurs only after successful authentication.
5. Device private keys never exist on the server.
6. Codex/OpenAI credentials never exist on Android.
7. Pairing codes are temporary and one-use.
8. Replayed authenticated requests are rejected.
9. Personal Admin/Hermes state is untouched.
10. Logs contain no capture text or authentication/provider secrets.

## Stop conditions

Stop before production mutation if:

- the implementation has unresolved BLOCKER/MAJOR security findings;
- authenticated failure paths can invoke the provider;
- replay protection is not persistent across restart;
- Caddy would require exposing FastAPI directly;
- rollback cannot be isolated to Quick Aside;
- deployment would require modifying Personal Admin/Hermes/Tailscale state.

Stop on the first real deployment validation failure.
