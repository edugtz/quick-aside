# ADR-0004 — Public authenticated Quick Aside gateway ingress

Status: Accepted
Date: 2026-09-13

## Context

Quick Aside must reach its AI gateway over normal Wi-Fi or mobile data without
requiring Tailscale, another VPN application, or Personal Admin.

Earlier planning preferred private-network-only ingress. QAG-3 preflight showed
that Tailscale is already used independently by Personal Admin, but Quick Aside
does not need that dependency.

## Decision

Quick Aside uses a dedicated public HTTPS ingress owned by Quick Aside.

Runtime topology:

    Android Quick Aside
      -> HTTPS
      -> Caddy :443
      -> 127.0.0.1:2588
      -> quickaside-gateway
      -> Codex exec --ephemeral
      -> GPT-5.6 Luna / Low

The gateway itself remains loopback-only.

Tailscale is not required for Quick Aside operation. Quick Aside must function
when Tailscale is running, stopped, disconnected, or absent.

## Client authentication

Each Quick Aside installation owns an EC P-256 key pair generated by Android
Keystore. The private key never leaves Android Keystore.

The server stores only the public key and device metadata.

Authenticated requests to `/v1/interpret` use ECDSA SHA-256 signatures.

Canonical signed payload version 1:

    QA1
    POST
    /v1/interpret
    <device-id>
    <unix-timestamp>
    <nonce>
    <lowercase-sha256-hex-of-exact-request-body>

Required headers:

- `X-QA-Device-Id`
- `X-QA-Timestamp`
- `X-QA-Nonce`
- `X-QA-Signature`

The signature is base64url-encoded DER ECDSA output without padding.

## Replay protection

- accepted timestamp skew: maximum ±120 seconds;
- nonce: minimum 128 random bits;
- an accepted `(device_id, nonce)` cannot be reused;
- accepted nonce state persists long enough to outlive the timestamp window;
- replay protection survives gateway restart.

## Device enrollment

Enrollment uses a server-generated, short-lived, one-time pairing code.

`POST /v1/pair` registers:

- pairing code;
- device id;
- device label;
- X.509 SubjectPublicKeyInfo public key.

Pairing codes are stored only as hashes, expire quickly, and are consumed
atomically.

Pairing-code creation and device revocation are local server administration
operations, not public admin APIs.

## Auth state

Quick Aside may use a Quick Aside-owned SQLite database under
`/var/lib/quickaside` for authentication metadata only:

- registered device public keys/status;
- pairing-code hashes and expirations;
- anti-replay nonce state.

It does not store captured user content.

## Server-side protections

- Caddy owns public TLS.
- FastAPI remains bound to `127.0.0.1:2588`.
- `/readyz` is not publicly routed.
- `/v1/interpret` requires valid device authentication.
- `/v1/pair` requires a valid one-time code.
- request bounds remain enforced.
- rate limits exist for pairing and interpretation.
- logs must not contain capture text, signatures, pairing codes, provider
  credentials, or private keys.
- Codex OAuth remains server-side under the dedicated Quick Aside service user.

## Isolation

Quick Aside must not depend on or modify Personal Admin, Hermes,
`/home/hermes`, `personal-admin-ack.service`, `hermes-gateway.service`,
`svc:personal-admin-ack`, or their credentials/state.

Sharing the same VPS does not create an application dependency.

## Consequences

This creates more public attack surface than tailnet-only ingress, so QAG-3
requires HIGH-ASSURANCE implementation and real external-network testing.

In return, Quick Aside has no VPN/Tailscale runtime dependency and uses the
normal Internet path from Android.

This ADR supersedes only the private-network-only ingress assumption in earlier
Quick Aside gateway decisions. Gateway ownership, provider isolation, local
validation, Codex runtime, and credential separation remain valid.
